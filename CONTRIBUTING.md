# Contributing

1. Open an issue describing the change or bug without including personal data, credentials, customer reports, or live identifiers.
2. Create a focused branch and keep commits limited to source code and sanitized documentation.
3. Do not commit `.env` files, local configuration, secrets, database dumps, generated reports, backups, access codes, or private session logs.
4. Run the relevant frontend build and PHP syntax checks before submitting a pull request.
5. Include synthetic data in examples and screenshots.

For a suspected vulnerability, contact the project maintainers privately. Do not publish a working exploit or secrets in a public issue.
